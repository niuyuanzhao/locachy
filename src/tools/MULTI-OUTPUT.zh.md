# 直连程序的原生多屏布局

[English](MULTI-OUTPUT.md)

1 号进程通过 DRM lease 把各直连程序拥有的屏幕交给它。锁定期间，锁屏拥有全部可用输出。
认证会话和密码缓冲只有一份；多个显示器不会增加 PAM 事务，也没有各自独立的解锁状态。

`screen_extended(1)` 选择已有的逐输出原生画布。布局文字之前先用
`screen_output_select` 选屏，行列数、像素尺寸和字体缩放就描述该屏。
未选择此模式的程序仍使用保持宽高比、居中的镜像画布。无法启用原生画布时保留镜像模式。

## 锁屏

锁屏在每块原生画布上分别布局同一份时钟、密码框、设备状态和错误。
较矮的屏幕先去掉装饰性空行，必要时再省略时钟、日期或用户名；密码、错误和底部提示保持分离。
每块画布清理全部像素，包括整数字符格之外的边缘。重新收到 lease（`K_SHOWN`）只重绘，
不清除输入中的密码，不重新开始认证。显示拓扑变化不代表认证或解锁。

## 文件管理器

files 只有一份浏览状态（标签页、文件夹内容、选择和操作），但每屏独立布局，
不再把第一屏的截图放大缩小到其他屏。绘制辅助屏时保留当前输入屏的滚动对齐和待处理的
跟随选择请求。输入屏最后绘制，因此共用的命中区域准确对应这块屏上的文件格和按钮。

指针事件先选择所属屏，再按这块屏重建布局后判断命中。桌面的逻辑像素转换成该屏原生像素，
用于框选和拖拽定位。文件拖拽可以进入另一屏；框选锚点属于原先的网格，跨屏便取消。
输出、模式或缩放变化会取消依赖像素坐标的拖拽和下拉状态，不改变文件夹或当前选择。
对话框留在打开它的那块屏；点击另一屏不会因为字符坐标相同而误按确认按钮。

files 暂时启用原生布局，退出时恢复调用方此前的屏幕模式和绘图目标。
设置、软件包等程序调用的文件选择器，以及仅拥有单屏的调用方，同样遵守此规则。
home 不再把 files 切回按第一屏绘制的镜像模式。

## 验证

- `tools/test-lock-layout.c`：两块不同尺寸画布、大字短屏、竖向尺寸画布、
  保持单一认证状态的拔插与恢复，以及镜像后备。无需 PAM、DRM 设备或运行中的锁屏。
- `tools/test-lock.c`：私有 PAM 服务继续验证密码、指纹、人脸空闲停止、清空和错误密码行为。
- `tools/test-files.sh`：文件浏览与操作，以及原生不同尺寸字符格布局、逐屏命中、
  缩放指针坐标转换、框选跨屏、真实浏览循环的 `K_SHOWN` 处理、镜像/原生模式切换；
  普通和 AddressSanitizer/UndefinedBehaviorSanitizer 构建。

这些设备无关检查与真实 KMS/显示器验收分开。它们不代表已经支持输出旋转：
当前显示器配置保存模式、缩放和位置，没有旋转变换字段。
