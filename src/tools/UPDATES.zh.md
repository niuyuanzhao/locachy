# 软件包与源码更新

[English](UPDATES.md)

`packages` 在应用前显示计划。`locachy-pkg plan` 和
`locachy-pkg apply [TARGET...]` 就是该界面使用的后台。检查不会安装软件源的包，
也不会在宿主执行下载的配方。

## 先源码，再更新与之匹配的宿主

选中 LOCachy 的源码更新时，应用先安装该源码及其包管理工具。新的更新程序
重新检查后，才更改宿主软件包或重建容器。因此配方和合约来自同一份已安装源码，
不再是旧配方配新测试。只应用宿主时，保留已安装源码及其测试。

源码已安装但构建失败时，仍保留“未构建”标记。之后检查必须继续提供程序重建；
仅宿主包版本相同，不代表新程序已经构建。包管理工具安装或软件包声明失败时，
应用会先重试这份源码的准备步骤，再规划宿主。第二阶段保持在所选源码上；最后
检查发现的新提交留给下一份计划，不在更新途中悄悄安装。

`declare-packages` 记录基础及可选模块的软件包定义。源码为已启用模块新增的包
自动进入 `/etc/locachy/packages`；明确删除的包不会重新加入。没有记录时，
以随源码附带的 08d2a66 定义为起点，不假定所有可选模块均已启用。这里以模块
首个包是否已声明判断启用状态。该脚本只声明，不安装。

已声明但缺失的软件源包，与宿主事务一起固定，并装进各候选包的一次性构建、
测试根及宿主最终事务。不能再靠手工补一个新库才能让新测试编译。
AUR 及本地构建仍有各自独立、明确的失败路径。

## 软件包合约

本地补丁包在一次性根中以非特权用户构建，使用固定的软件源快照。精确封存的
产物一同装进另一个一次性根，可信合约在其中执行，不暴露宿主显示或输入设备。
证据记录完整产物集合、目标包、源码哈希及必需合约编号。不一致则停止宿主更新，
不能以编译器成功退出来绕过。

`tools/test-local-packages.py`、`test-update-transaction.py` 及
`test-prepared-builder.py` 用替身检查流程，不证明新的一组真实软件包已通过合约。
实际运行及限制另记在仓库的 `REGRESSIONS.zh.md` 中。

## 添加包名

宿主的添加输入框接受空格分隔的多个包名，每个作为独立参数传递。后台先验证
整批请求，依次查询本地配方、软件源及 AUR，再更改清单。未知包名和查询失败
均不更改清单。既有的多名同一行按独立包读取；删除一个保留其他名字。

添加、删除声明仍会运行系统对账，而不只是单包 pacman 命令。
失败输出保存在 `/run/locachy/packages.log`；prepared 更新失败时，计划及合约日志
保留在 `/var/lib/locachy/local-packages/transactions/` 下。不能为了越过错误而删除
这些日志或跳过合约。
