# 威胁烈度与胁迫密码

[English](DURESS.md)

两组独立设置，都在「安全」页：

- **威胁烈度**（rc.conf 的 `lock_mode`：`low` 或 `high`；旧值 `normal` 也视作 `low`）
  决定*有哪些解锁方式*。低：密码，另加已开启的指纹或人脸，以及已绑定的 TPM。高：所有
  要求输入的地方都只认密码：
  - 开机时只认 LUKS 口令（TPM 不再打开磁盘）；
  - 锁屏只认密码；
  - `sudo` 只认密码。
  切换到高烈度会删除 TPM 的密钥槽（`locachy-tpm clear`），只要还留着一个，设置就不切换。
  TPM 令牌密封给本机 PCR 密钥签过的每一个引导镜像，包括上一个镜像和从 ESP 拷走的
  任何旧副本，而不只是当前镜像；留下密钥槽，这样的镜像就能打开磁盘。切回低烈度后，
  指纹与人脸的开关恢复原样；TPM 需要重新绑定。威胁烈度在设置里切换，会重建引导镜像，
  下次开机生效。

- **胁迫密码**（rc.conf 的 `duress_enabled`，验证器在 `/etc/locachy/duress`）决定
  *第二个密码做什么*。在要求输入密码的地方（开机口令、锁屏、`sudo`）输入胁迫密码，
  会立即销毁加密磁盘并关机。它和威胁烈度是两个独立决定：可以在低烈度下启用胁迫，
  也可以在高烈度下不启用。

## 胁迫密码销毁什么

`duress_wipe`（base/duress.c）会覆写两个 LOCachy LUKS2 分区（标签 `locachy-crypt`
和 `locachy-swap-crypt`）数据偏移之前的部分，共两遍，第一遍是随机数。这覆盖两个
二进制头、JSON 区以及全部密钥槽：口令槽、TPM 的密封密钥，以及任何恢复槽。没有它们，
任何人都无法解密数据，包括知道口令的人。之后还会删除签名引导镜像的密钥与胁迫验证器
本身，然后关机。

它**不会**清除 TPM。密封的数据在 LUKS 密钥槽里，而密钥槽已经没了；清除 TPM 还会
破坏同一台机器上其他系统的密封密钥（例如 Windows 的 BitLocker）。

如果系统上没有 LOCachy 的 LUKS2 分区，它什么也不做。设置和 `locachy-duress set`
在那种系统上拒绝启用：删除文件的擦除既不快也不彻底。

## 优先级：真实凭据永远优先

- **开机：** 先试口令。只有口令一个分区也打不开时，才检查胁迫密码。
- **锁屏和 `sudo`：** 输入的文本先与 `/etc/shadow` 中的登录密码比对
  （`duress_login_check`）。只有明确不一致（结果 0）才可能销毁；`/etc/shadow` 读不到
  （结果 -1）则永不销毁。这覆盖了正确密码被 `pam_faillock` 锁定拒绝的情况。
- `locachy-duress set` 拒绝与登录密码相同的胁迫密码，以及能打开磁盘的密码
  （`cryptsetup open --test-passphrase`）。这样的密码永远不会触发销毁，拒绝才是诚实的答复。

## 设置步骤

1. 设置 → 安全 → **胁迫密码** → Enter。输入两次，至少 8 个字符，且与登录密码、
   磁盘口令都不同。
2. 设置 → 安全 → **胁迫密码销毁磁盘** → 开启。这会在 `/etc/pam.d/sudo` 第一行 auth
   之前（开启了指纹或人脸时，在 `pam_locachy_any.so` 那一行之后）加入
   `auth optional pam_locachy_duress.so`，并重建引导镜像，新镜像携带验证器。这一行必须
   在前面：Arch 的 `system-auth` 遇到错误密码会结束整个栈（`pam_faillock.so authfail`，
   `[default=die]`），放在后面的模块永远看不到胁迫密码。它只读一次密码
   （`pam_get_authtok`），再交给 `pam_unix`（`try_first_pass`），所以 sudo 仍然只问一次。
3. 可选：**威胁烈度** → 高。

撤销：在胁迫密码行上连按两次 Delete（清除验证器并关闭胁迫），或运行
`locachy-duress clear`。

## 局限，直说

- **验证器位于未加密的 ESP 上。** 初始化内存盘（在签名的 UKI 里，而 UKI 在 FAT 的
  ESP 上）携带它，以便开机口令提示能够核对。拿到磁盘的人可以离线猜测，参数是
  PBKDF2-HMAC-SHA256、600,000 轮。胁迫密码的强度只取决于它本身的长度：请像选口令
  一样认真选它。
- **`sudo` 也包括在内**，因为 GrapheneOS 覆盖每一个凭据提示。`sudo` 提示里误输的
  胁迫密码就是一次销毁。若嫌太锋利，从 `/etc/pam.d/sudo` 删掉那一行即可；开机和锁屏的
  检查不受影响。
- **上一个引导镜像保留它制作时的策略。** 固件的“LOCachy (Previous)”启动项启动上次
  重建之前的镜像：启用胁迫、更改胁迫密码或切换威胁烈度之后，那个镜像在下次重建前仍是
  旧策略，它的开机提示不检查胁迫密码，或检查旧的那个。它能打开的不比当前镜像多：
  仍然要输入口令，高烈度下也没有 TPM 密钥槽可用。
- 销毁按设计不可逆。LOCachy 不保留任何头的副本。
- 锁屏从 root 进程执行销毁；关机使用内核的 reboot 调用，需要 root 具有的能力。

## 测试情况

`tools/test-duress.sh` 只针对临时文件构建 `base/duress.c`（验证器格式与权限、损坏或
强度不足的验证器、没有 LUKS 时的空操作，以及在伪造的 LUKS2 镜像上销毁的精确范围，
其他分区保持不变），并为进程 1 构建（musl，静态）。销毁本身在关闭关机的情况下测试，
因此没有任何测试触及真实磁盘、密钥或 TPM。

`tools/test-init-unlock.py` 运行进程 1 自己的开机解锁函数，磁盘、TPM 和胁迫验证器
都是替身。启用时，胁迫密码只在先用它试过口令之后才销毁；真实口令，或任何能打开
磁盘的文本，永远不会销毁。未启用时，胁迫密码只是错误的口令。高烈度下不尝试任何
TPM 令牌，即使它能打开磁盘。

在虚拟机里（QEMU 加 OVMF，装在 LUKS2 上的 LOCachy，每个用例用其磁盘的一份新副本），
低和高两种威胁烈度下：
- 开机：错误口令会再问一次，磁盘上什么都不变。胁迫密码会关机：两个分区的两份 LUKS2
  头（主头和备份头）以及密钥槽都被覆写，ESP 的引导扇区保留，下次开机进不了系统；
- 锁屏和 `sudo`：错误密码什么都不变，登录密码能解锁；胁迫密码同上销毁；
- 关闭胁迫（删除验证器，重建引导镜像）之后：开机时输入同一个密码只是错误的口令。

那台虚拟机没有 TPM：高烈度跳过 TPM 只由上面的单元测试验证。尚未在真机上测试。
