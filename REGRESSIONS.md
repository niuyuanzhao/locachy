# Regression acceptance

This is the release checklist for reported regressions. A passing unit test is not hardware acceptance. Keep an item open until its stated acceptance checks have evidence. Keep reported behavior, a reproduced cause, a local fix, a published fix, and an accepted installation distinct.

## Release rules

- Build and link the complete target Linux source tree before publishing to the update branch.
- Run the real prepared-package contracts against the same target repository snapshot and co-installed local package archives. Do not bypass a failed contract.
- Test event delivery, geometry and hardware behavior separately from package installation and configuration generation.
- Add a regression test for each reproducible defect. Mock tests and cross-compilation supplement, but never replace, Linux integration tests.
- Deliver generic fixes through the repository and normal updates. Preserve existing configurations, explicit optional-package choices and failed-update logs.
- Applying an update does not authorize rebooting, restarting a lock, changing keyboard mappings, recording biometrics, or starting visible applications.
